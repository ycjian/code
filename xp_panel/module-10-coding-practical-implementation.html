10.1 Producer–Consumer 题的口头设计

先确认：单机还是分布式、是否要求 ordering、queue 是否 bounded、failure/retry、shutdown semantics、CPU-bound 还是 I/O-bound。

Python 线程版骨架：

from queue import Queue
from threading import Thread

STOP = object()

def process(item):
    ...  # domain-specific, should either succeed or raise a classified error

def handle_failure(item, exc):
    ...  # retry, dead-letter, or record terminal failure; must be bounded

def producer(items, q: Queue, n_consumers: int):
    try:
        for item in items:
            q.put(item)          # bounded queue provides backpressure
    finally:
        for _ in range(n_consumers):
            q.put(STOP)

def consumer(q: Queue, handle):
    while True:
        item = q.get()
        try:
            if item is STOP:
                return
            handle(item)         # production: classify retryable errors
        except Exception as exc:
            handle_failure(item, exc)
        finally:
            q.task_done()

q = Queue(maxsize=1024)
n = 8
workers = [Thread(target=consumer, args=(q, process), daemon=False)
           for _ in range(n)]
for w in workers:
    w.start()
producer_thread = Thread(target=producer, args=(source, q, n), daemon=False)
producer_thread.start()
producer_thread.join()           # all work and STOP markers are now enqueued
q.join()
for w in workers:
    w.join()

主动指出：handle 失败后怎么 retry/dead-letter 取决于语义；Python threads 适合 I/O-bound，CPU-bound 需要 multiprocessing/native/vectorized/distributed。若 STOP 之前 producer 异常，finally 确保 shutdown。真实生产还需要 cancellation、metrics、timeout 和 ordered commit。

10.2 合并 K 个有序大文件

用 min-heap 保存每个文件当前 record，空间 O(K)，时间 O(N log K)；流式读写，不把所有数据放内存。若 K 太大超过 file descriptor limit，分多轮 external merge。处理 malformed record、stable ordering、duplicate policy、checkpoint/output atomic rename。

10.3 处理超大 log / file

  • 流式 iterator；按 block 读并处理跨 block partial record。
  • bounded buffer；批量 write；避免 per-record object allocation。
  • 可按 byte range 分片，但 worker 起点要前进到下一个 record boundary。
  • 输出 deterministic partition；失败重试不重复 publish。
  • 若全局 sort，用 external sort：chunk sort → spill → k-way merge。

10.4 Thread-safe bounded queue 要讲什么

Circular buffer + mutex + not_empty/not_full condition。put 在 full 时 while-loop wait；get 在 empty 时 while-loop wait，必须用 while 防 spurious wakeup。修改 state 后 signal 对方。定义 close 后 producer/consumer 行为，避免 shutdown deadlock。面试时优先写 correctness，再优化 lock contention。

10.5 LRU Cache

Hash map + doubly linked list，get/put O(1)。追问：thread safety、capacity=0、update existing、eviction callback、TTL。分布式场景不能把单机 LRU 答案硬扩成 distributed cache；需要一致性、sharding、replication 和 invalidation 另行设计。

10.6 Coding 时必须说出的句子

  • “我先写 correct baseline，再优化。”
  • “这里的 invariant 是……。”
  • “时间复杂度是……，额外空间是……。”
  • “这个异常是否应该 retry 取决于 side effect 是否 idempotent。”
  • “我会测 p95/p99 和 memory，不只看平均 throughput。”

Prompt：合并 camera/LiDAR/trajectory stream

先问是 offline sorted input 还是 online out-of-order。Offline 用 K-way merge；online 需要 per-stream watermark：只有当所有必要 stream 的 watermark 都越过 t + tolerance 时，才安全输出时间 t 的 aligned record。某一路永久缺失时按 timeout 策略输出 missing mask 或 quarantine，不能无限等。

Prompt：并行处理后保持顺序

Producer 给 item 分配 monotonic seq；worker 并行返回 (seq, result)；coordinator 用 map/min-heap 暂存，从 next_seq 连续 commit。Reorder buffer 必须 bounded，否则一个慢任务会让后续结果无限堆积。可选择 backpressure、timeout/retry，或如果业务允许就放弃 global order。

Prompt：如何测试 producer-consumer？

  • empty input、单 item、queue size 1；
  • producer/consumer 任一方更快；
  • handler exception、producer exception；
  • shutdown/cancel 时 queue full/empty；
  • 每个 item 恰好有一个 terminal outcome（success 或 recorded failure）；
  • stress test 检查 deadlock、lost item、duplicate side effect。
