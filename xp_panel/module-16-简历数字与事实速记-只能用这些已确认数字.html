16.1 不记得或不能披露内部数字时的安全答法

不要猜，也不要只说 “confidential” 后停止。用可验证的 engineering detail 继续回答：

Scale：

“我不想给出不准确的内部 node/QPS 数字。可以确认的是这是 production multi-tenant workload；capacity planning 主要由 [bytes / task duration / GPU memory / request class 中真实项] 驱动。我可以具体解释 partition、autoscaling signal 和我们遇到的 bottleneck。”

SLO：

“具体内部 SLO 不便引用；我们实际把 success、p95/p99 latency、queue age、retry/recovery 和 resource utilization 分开监控。这个项目最关键的 guardrail 是 [真实项]。”

Impact：

“这个项目简历中没有写数字，因此我不想临场创造 percentage。可确认的结果是 [接入 capability / production rollout / failure recovery / independent scaling 中真实项]。如果要说明验证方式，我们比较了 [真实 baseline 和 metric]。”

Ownership：

“我 owned architecture/contract 和 rollout outcome；我亲自实现 [真实模块]；其他 execution component 由合作团队交付，我负责 interface、review 和 integration。这样可以准确区分我的技术领导与团队贡献。”
