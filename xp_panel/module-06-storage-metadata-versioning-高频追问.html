6. Storage / Metadata / Versioning 高频追问

Q：为什么用 Iceberg/Delta 这类 table format，object store 不够吗？

答：object store 只提供 blob namespace；table format 在其上提供 snapshot、schema evolution、partition evolution、atomic metadata commit、time travel 和 file-level statistics。它适合 curated metadata/feature table，但原始视频仍是 blob。选 Iceberg 还是 Delta 要看现有 compute engine、catalog、操作成熟度；不要把品牌选择说成原则。

Q：如何避免 small-file problem？

在 writer 端批量 flush，按 target file size 控制；后台 bin-pack compaction；metadata manifest 合并；训练侧读取 packed shards。Compaction 生成新 snapshot，旧 snapshot 在 retention/reader 安全窗口后 GC，不能边 compact 边让活跃 reader 失效。

Q：Dataset version 和 Git version 有什么差异？

Git 擅长小文本 diff，不能直接版本化 PB blob。Dataset version 保存 immutable manifest/snapshot 和生成 recipe；blob 可 content-addressed 去重；metadata/transform code 用 Git SHA。要能从 model checkpoint 回溯完整数据成员和 transform environment。

Q：Metadata catalog 挂了，训练是否停？

已 materialize 的 dataset manifest 应可独立读取，训练不应在每个 batch synchronous 查询 catalog。Catalog 是 build/discovery/control dependency；训练启动时解析并缓存 signed/immutable manifest。这样降低 blast radius，但新 dataset 创建和权限变更仍需要 catalog。

Q：一致性选 strong 还是 eventual？

按 invariant 分层：dataset version publish、ACL/policy、job ownership 需要强一致或 transactional compare-and-swap；search index、统计 dashboard、cache 可以 eventual consistency。关键不是全局选一种，而是明确哪些状态不能出现双写/丢失。

Q：如何支持多团队共享 dataset？

稳定 DatasetSpec/API、schema registry、namespace、RBAC/ABAC、quota、cost attribution、quality certification、immutable published version。共享 raw/curated base，团队可有私有 derived view。Promotion 有 owner 和 gate；deprecation 有 usage telemetry 和 migration window。
