4. VLA / World Model：基础设施工程师必须能讲的知识

4.1 概念

  • VLA (Vision-Language-Action)：输入视觉/多传感器观测与 language/task context，输出 action 或 trajectory token/continuous control。
  • World Model：学习环境 dynamics，给定历史观测和 action，预测未来 state/observation/latent/reward；可用于 representation learning、planning、simulation 和 counterfactual rollout。
  • 数据单位通常不是独立 frame，而是 sequence/episode；因此 temporal consistency、action alignment、sequence packing 和 variable length handling 非常重要。

4.2 数据 pipeline 的特殊要求

  • Observation、language/route instruction、ego state、action、future trajectory 必须在统一 timeline 对齐。
  • 明确 action 是 planner output、driver command 还是实际执行结果；command 与 realized motion 不同。
  • Sequence window 要定义 history horizon、prediction horizon、stride、boundary handling。
  • Tokenization/normalization、camera ordering、calibration 和 coordinate convention 必须版本化。
  • 训练 sampling 要兼顾自然分布、rare/safety event、geographic/behavior diversity 和 curriculum。
  • Offline logs 有 causal confounding：只观察到当时 policy 的 action 及结果，不能把未发生的 counterfactual 当 ground truth。
  • Open-loop prediction 好不代表 closed-loop safe；评价要覆盖 simulation/closed-loop rollout。

4.3 Evaluation 分层

  1. Data validation：sequence continuity、alignment error、missing modality。
  2. Offline metrics：trajectory displacement/error、collision proxy、action accuracy、calibration；按 scenario slice 报告。
  3. Simulation：closed-loop intervention、collision、comfort、route completion、rule compliance。
  4. Shadow/fleet validation：有严格 safety gate 和 staged rollout。

面试答案亮点：

“我会让每个 metric 都能反查到 dataset version、model checkpoint、scenario IDs 和 software/config version。这样 evaluation 不是一个 dashboard 数字，而是下一轮 failure mining 的可执行输入。”

4.4 Episode / Sequence 的数据 contract

Frame 不是充分抽象。推荐以 EpisodeManifest 作为 logical unit：

EpisodeManifest
  episode_id / parent_drive_session
  event-time start/end / route segment
  software + map + calibration versions
  sensor streams[]:
    modality / clock / frequency / codec / artifact refs
  ego states[] / planner commands[] / realized actions[]
  language or route instruction
  scenario taxonomy + quality flags
  annotation refs + label schema/model versions
  lineage / privacy / split assignment

三个 invariant：

  1. Time：所有 modality 保留原始 timestamp/clock domain；alignment 是可版本化 transform，不覆盖 raw time。
  2. Space：calibration、ego pose、coordinate convention 明确；缺 calibration 的数据不可悄悄加入训练。
  3. Causality：在预测时刻之后才可观察的信息不能进入 input feature；future trajectory 只能作为 target/evaluation。

4.5 Sequence slicing、packing 与 split

假设 history horizon 为 H、prediction horizon 为 P、stride 为 S：每个样本是 [t-H, t] → [t, t+P]。面试时要主动问：

  • Episode 边界是否允许跨 trip、地图版本或 software build？通常不允许。
  • Sensor dropout 时丢弃、mask 还是 impute？取决于模型是否要学习 degraded mode，但必须显式标记。
  • Variable length 如何 batch？按 length bucket、token/frame budget packing，减少 padding 和 rank skew。
  • Split 不能随机按 frame；应按 session/route/time/region group split，并用 near-duplicate 检测防止相邻 clip 泄漏。
  • Overlapping windows 会制造大量 near-duplicate；训练 sampling 和指标统计要按 parent episode 校正。

4.6 VLA 数据里最容易答错的 action

必须区分：

  • commanded action：planner/controller 想执行什么；
  • executed control：真正发送到 actuator 的控制；
  • realized motion：车辆最终运动，受到 dynamics 和环境影响；
  • expert intervention：人类接管或 safety override。

如果把 realized motion 当成 commanded action，模型可能学到动力学结果而非决策；如果只保留成功轨迹，会有 survivorship bias。Intervention 前后的 window、policy version 和 reason code 对 failure learning 非常重要。

4.7 World Model 数据的额外难点

  • Stochastic future：同一 observation 可能有多个合理未来，不能只用单一 pixel/trajectory error 判断。
  • Action-conditioned dynamics：dataset 必须包含 action 与后续 state 的严格对齐。
  • Partial observability：有限 sensor view 不代表世界中对象消失；需要 temporal context/latent state。
  • Compounding error：one-step prediction 好，长 rollout 仍可能漂移；evaluation 要按 horizon 报告。
  • Policy coverage bias：log 只覆盖现有 policy 访问过的 state/action；模型无法凭空学习未探索 counterfactual。
  • Simulation gap：sim 数据可覆盖 rare event，但要标识 domain/source，并测 sim-to-real gap，不能无区分混合。

4.9 Failure Mining / Active Learning 的优先级

可以定义概念性 priority：

priority = severity × novelty × uncertainty × coverage_gap × expected_utility
           / (labeling_cost + processing_cost)

这不是要求线上真的用乘法；重点是表明不只靠 uncertainty。流程：

  1. 由 offline/simulation/shadow evaluation 产生 failure candidate。
  2. 用 scenario taxonomy、embedding 和 metadata 去重/聚类。
  3. 保留 cluster representative，避免一个事故产生几千个相邻 frame。
  4. 路由到 auto-label/human review/recollection/simulation。
  5. 生成新 DatasetSpec，记录 sampling reason 和 weight。
  6. 训练后按相同 slice 验证，同时看相邻 slice regression。

4.10 Yx Gxx 可能连续追问

Q：如何定义一个 VLA training sample？ A：不是 frame，而是绑定 history observation、instruction/context、ego state、action target、future horizon、calibration 和 provenance 的 episode window。具体 H/P/S 由模型和 latency target 决定。

Q：多路 camera 频率不同怎么办？ A：保留各自 event time，定义 reference timeline 和 tolerance；选择 nearest/interpolation/aggregation 要版本化。超 tolerance 写 missing mask 或 quarantine，不能静默复制上一帧。

Q：如何保证 dataset reproducible？ A：pin resolved episode IDs、source snapshots、windowing code/container、label/calibration/map version、sampling seed/weight、split manifest；query 本身不够。

Q：Rare case 越多越好吗？ A：不是。过度 oversample 会偏离 deployment distribution、降低 common-case performance。保留 unbiased base，rare sample 带 weight/source；用 slice gain 和 regression gate 调整比例。

Q：Auto-label 怎么上线？ A：新 labeler 先跑 frozen golden set 和 shadow dataset；比较 precision/recall/disagreement、关键 slice 和 downstream model utility；label 带 model/version/confidence，旧 label 不原地覆盖。

Q：Open-loop metric 提升但 closed-loop 下降？ A：先按 scenario/horizon 找 divergence，检查 distribution shift、compounding error 和 metric proxy mismatch；以 closed-loop/safety gate 为准，冻结 rollout，回流相应 failure episodes。不能用平均 open-loop 指标否定 closed-loop regression。
