11. 三位 Panel Interviewer 的定向答题重点

11.1 Yxxxx Rxx：Distributed Systems & Data Platform

最可能深挖：PB/EB storage、ingestion correctness、distributed processing、bottleneck、architecture trade-off。

开场固定讲 context-aware AI Infra 的 correctness/failure recovery；被追问真实 data scale 时再切到 50B+ multimodal platform。 设计题优先 deep dive：data/control plane separation + immutable raw + idempotent ingest + DatasetSpec + lineage。 Senior 信号：清晰 SLO、failure domains、reconciliation、cost model。

可能问题：

  1. Design autonomous driving data infrastructure。用第 2 章完整回答。
  2. 如何保证 fleet upload 不丢不重？答 at-least-once + checksum + idempotency + manifest transaction + reconciliation。
  3. PB/EB 数据怎么查？答分层 metadata/filter/vector index；blob 不进数据库；索引可重建。
  4. 如何处理 skew/straggler？答 cost-aware partition + metrics + split/steal/speculation。
  5. 你做过最难的 architecture trade-off？讲拆分 execution paths 与平台复杂度之间的权衡。

结尾可问：

“当前 data platform 最难的 scale boundary 是 fleet ingestion、scenario mining、dataset build，还是 training read path？团队用什么 SLO 判断它是 data infra 问题而不是 model code 问题？”

11.2 Yx Gxx：Foundation Model Data Pipeline / VLA / World Model

最可能深挖：sequence data、multimodal alignment、dataset quality、failure mining、research iteration speed。

开场项目选：context-aware multimodal platform，再主动映射 VLA/world model。 设计题优先 deep dive：scenario clip model + temporal alignment + DatasetSpec + quality/coverage + feedback loop。 避免只讲 infrastructure availability；要连接 model outcome。

可能问题：

  1. 好 dataset 如何定义？用第 2.8 节六层框架。
  2. camera/LiDAR/trajectory 怎么管理？讲 clock、calibration、coordinate frame、missing mask、sequence window。
  3. 如何缩短 research iteration？预计算可复用 base feature，declarative dataset，incremental materialization，cache，自动 QA/eval，一键 lineage/reproduce。
  4. failure case 如何回流？severity × novelty × uncertainty × coverage gap，且保留 unbiased sample。
  5. VLA 和普通 image classification pipeline 最大区别？sequence/action/causality/closed-loop。

结尾可问：

“团队目前对 dataset quality 的 north-star 更偏 coverage、closed-loop improvement，还是单位 compute 下的 marginal data utility？failure mining 的结果能否自动生成下一版 DatasetSpec？”

11.3 Bx Txxx：Training Scalability / Ray / Technical Leadership

最可能深挖：training platform、Ray、GPU utilization、multi-tenant scheduler、end-to-end ownership。

开场项目选：context-aware platform 的 shared CPU/GPU execution。 设计题优先 deep dive：resource isolation + data feeding + fault recovery + observability。 Leadership 回答要覆盖多团队接口、migration、rollout 和长期演进。

可能问题：

  1. Ray 为什么适合？答 Python/ML task/actor/heterogeneous resource，同时承认 Spark 的 table workload 优势。
  2. GPU 空闲怎么查？用第 3 章实验式排障，不要先猜 storage。
  3. 共享集群怎么防 noisy neighbor？quota、priority、fair share、gang scheduling、preemption policy、namespace、cost attribution、SLO class。
  4. 平台标准化与 researcher flexibility 如何平衡？稳定 artifact/dataset/resource/policy contract；transform 可插件化；提供 paved road 和 escape hatch，escape hatch 仍受安全/成本边界约束。
  5. 如何 influence without authority？见下一章。

结尾可问：

“Ray 在团队里主要承担 data processing、training orchestration 还是 serving？当前限制规模化的瓶颈更多是 scheduler/object store，还是数据格式与 locality？”

11.4 三套 15 分钟连续追问演练

不要只背单题。以下追问故意层层深入；练习时每个短答 30–60 秒，面试官表示兴趣再展开。

Yxxxx：从平台设计追到 correctness

1. Design an autonomous driving data platform. 先给第 2.2 节全景；主动选 ingestion correctness 与 dataset version 深入。

2. Upload 成功但 catalog 写失败怎么办？ Blob 处于 orphan/unpublished；服务端只有 checksum 验证且 metadata commit 后才发布。Reconciler 根据 upload session/idempotency key 补 metadata 或按 TTL 清理，reader 不读 unpublished blob。

3. Event 重复消费怎么办？ At-least-once + deterministic artifact/task ID；sink compare-and-swap/unique key；重复 event 返回已有 committed result。Side effect 必须 idempotent 或用 outbox/transaction boundary。

4. Reconciler 自己重复或并发怎么办？ Work item lease + fencing token；repair operation 仍幂等。Reconciler 不是 correctness 的例外路径，不能依赖“只跑一个实例”。

5. PB 数据如何 partition？ 逻辑 partition 按常用 filter 和生命周期；物理训练 shard 按读取 locality/target size。避免 vehicle_id 等高基数字段直接产生 millions of partitions；监控 skew 和 small files。

6. Metadata index 与 source of truth 不一致？ Catalog/table snapshot 是权威状态，search/vector index 是 versioned projection。CDC/event replay 重建；ACL/security fail closed；普通搜索结果允许 bounded eventual consistency。

7. 最大 trade-off？ Raw preservation 保证 replay/reproducibility，但成本高；用 tiered retention、triggered upload 和 derived artifact TTL，不能在没有 lineage 的情况下随意删 raw。

Yi：从 VLA sample 追到 data flywheel

1. What is one VLA training sample? Episode window：history observation + context/instruction + ego state + action/trajectory target + calibration/provenance。

2. Camera/LiDAR/action 如何同步？ 保留 event time/clock domain，以 reference timeline 对齐；calibration 和 interpolation strategy 版本化；超 tolerance 使用 mask/quarantine。

3. 如何 split？ 按 drive session/route/time group split；相邻 overlapping windows 和 near-duplicate 不跨 split；derived artifact 继承 parent split。

4. Dataset quality 怎么衡量？ Integrity/alignment/label 是 gate；coverage/diversity/distribution 是 selection；最终看关键 slice 的 model utility 和 regression。

5. 如何找下一批数据？ Severity、novelty、uncertainty、coverage gap、expected utility / cost；cluster/dedup 后选 representative，保留 unbiased baseline。

6. Closed-loop 下降怎么办？ 停止 promotion；按 scenario/horizon 分 slice；检查 causal leakage、policy coverage、compounding error 和 proxy mismatch；将 failure episode 回流新 dataset，而不是只调 global loss。

7. 如何证明迭代更快？ 量化 data discovery→dataset publish→training start→evaluation 的 lead time；分别降低 query、materialization、validation、cache warmup 和 eval handoff，不用“pipeline 自动化了”作空泛结论。

Bo：从 GPU 低利用率追到 Ray/leadership

1. GPU utilization 低怎么办？ Synthetic data 隔离 input；trace read/decode/H2D/compute/NCCL；比较 ranks 和 scale curve。

2. 发现 CPU decode 跟不上？ 先提高并行/vectorize/prefetch；评估 offline precompute 或 GPU decode；以 end-to-end cost、storage amplification 和 experiment flexibility 权衡。

3. 为什么 Ray？ Python task/actor、heterogeneous CPU/GPU、ML workflow 和 streaming execution；结构化 SQL/大 shuffle 不排斥 Spark。

4. Ray object store OOM？ 限制 in-flight blocks、释放 ObjectRef、匹配 producer/consumer、调 block size；spilling 是 safety valve，不是 backpressure 替代品。

5. Actor crash 如何恢复？ 明确 restart/retry policy；constructor 重跑不恢复业务 state，需 durable checkpoint；外部 side effect 用 idempotency。

6. 多团队争 GPU 怎么办？ Workload class、quota/fair share、priority/preemption、gang scheduling、admission、cost visibility；交互 SLO 与 batch utilization 分开。

7. Researcher 不愿迁移平台？ 先找 migration friction，用 adapter/golden path/pilot 降成本；通过 time-to-first-run、reliability、cost 证明；保留 governed escape hatch，并用 telemetry 决定平台抽象是否需改。
