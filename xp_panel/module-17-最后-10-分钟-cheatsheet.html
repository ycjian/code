17.3 设计题 30 秒开头

“我先假设这是 PB–EB 级历史数据加持续 fleet 增量，训练主要按 multimodal clip/episode 顺序读取。我要优先保证 ingest durability、dataset reproducibility、build freshness 和 GPU feeding throughput。我会把大对象 data plane 与 metadata/control plane 分离：raw immutable object store 是 source of truth，manifest/catalog 负责 schema、lineage 和 version；distributed processing 生成 curated data，声明式 DatasetSpec materialize immutable snapshot，再做 training-oriented sharding/cache。最后用 evaluation/failure mining 生成下一版 dataset。下面我重点展开 ingestion correctness 和 dataset/training read path。”

17.4 GPU 低利用率 20 秒开头

“我不先猜原因。我会对 step time 做分解，用 synthetic data 区分 model compute 和 input path，再逐级增加 loader worker/node/GPU，trace read、decode、H2D、compute 和 NCCL。找到 critical path 后再决定 shard/prefetch/cache、CPU/GPU decode、topology 或 scheduler 优化，并以 end-to-end samples/sec 和 cost 验证。”

17.5 Dataset quality 20 秒开头

“我不会把好 dataset 等同于 label accuracy。先看 integrity 和 multimodal alignment，再看 ODD/scenario coverage、distribution、duplicate、label quality 和 split leakage；最终以固定 compute 下对关键 offline/closed-loop slices 的 marginal utility 判断。所有结论必须绑定 immutable dataset version。”

17.6 被问到不会的内容

“这个 domain-specific 细节我没有直接 production 经验。我先说明我确定的 invariant 和可能的 failure mode，再说我会用什么 measurement/experiment 与 domain expert 验证，而不假设一个答案。”

17.7 结束语

“我的核心优势是把多模态数据、分布式处理、检索和共享 CPU/GPU execution 作为一个端到端平台问题来做。我既能深入到 idempotency、partition、cache 和 bottleneck，也能在 Senior Staff 层面定义跨团队 contract、SLO、migration 和 ownership。我希望把这种能力用于 XPENG 的 dataset iteration 和 model data flywheel。”
