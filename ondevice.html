0B. 一句话回答模板#

What do you own?#

I own the execution platform between product features and AI models: request admission, model and runtime selection, local scheduling, media/PDF preprocessing, cache, artifact persistence, cloud fallback, and observability.

Why not call Core ML directly?#

Direct calls duplicate model loading, preprocessing, cache, fallback, and telemetry across features. A shared runtime provides one versioned policy and resource boundary.

What runs locally?#

Privacy-sensitive, latency-sensitive, offline-capable, and relatively small workloads: preview, OCR, embeddings, masks, tagging, lightweight denoise, and command planning.

What runs in cloud?#

High-resolution generation, large diffusion/VLM models, long video jobs, cross-device workflows, global retrieval, and expensive batch processing.

What makes this senior/staff work?#

The hard part is not invoking a model. It is managing resource admission, model compatibility, cache correctness, privacy boundaries, failure isolation, rollout, and one lineage across edge and cloud.

选择模板：

If the product is Apple-first and the model converts cleanly, I start with Core ML. I use ONNX Runtime or ExecuTorch when cross-platform model ownership or PyTorch runtime compatibility is a stronger requirement. I use MPSGraph for custom tensor graphs and MLX mainly for Apple-silicon research or local model experimentation.

0Q. Rapid-fire interviewer Q&A#

.mlmodel vs .mlpackage?#

.mlmodel 是单文件 model representation；.mlpackage 是 package directory，适合 ML Program、分离 weights/metadata。运行前都要走 compiled/prepared representation。Packaging 本身不保证更快。

Core ML vs Vision?#

Core ML 是 custom model runtime；Vision 是 image analysis request/observation framework，包含 system algorithms，也能通过 VNCoreMLRequest 调 Core ML。

CPU/GPU/ANE 怎么选?#

不硬编码“ANE最快”。按 model/device/OS profile 测 end-to-end latency、memory、energy 和 operator placement。Router 根据 SLO 与健康状态选。

为什么要 warmup?#

第一次可能包含 model load、compile/preparation、shape specialization、buffer/texture allocation。Warmup 用 representative input，不能阻塞 app launch，也不能把所有 model 都提前加载。

Batch 什么时候有价值?#

Background embeddings/OCR/tagging、同 model/shape、loose deadline。Interactive request 不应等待 batch window。

如何避免 OOM?#

Admission estimate、memory tokens、downsample/tiles、buffer pool、bounded page concurrency、evict recomputable artifacts、small variant、separate worker/XPC where available。

Cache key 为什么包含 model/preprocess?#

同一 asset 在不同 weights、crop、normalization、threshold 下 output 不同。不包含就是 correctness bug。

SQLite vs RocksDB?#

Apple local runtime 默认 SQLite metadata + files，简单、transactional。RocksDB 用于高写入 macOS/helper/backend KV workload，承担 compaction与运维。

OCR 为什么不全部上云?#

Privacy、offline、latency、bandwidth。Native text和Vision OCR可以先本地；复杂 layout/table 或高质量 extraction 才按 policy 上云。

OCR 为什么不处理所有 PDF page?#

有 native text 时直接 extract 更准、更快。先 classify native/scanned/hybrid，再选择路径。

PDF redaction 如何验证?#

删除底层 text/image/vector/hidden OCR，不只是画黑框；重新 extract/search，检查 metadata/attachment/incremental history，再做 visual verification。

Foundation Models 在系统里做什么?#

做 command understanding、structured plan、tool selection。它不直接拥有 file/network/pixel side effects；typed validator和authorized executor负责。

Private Cloud Compute 和 Amsterdam backend?#

PCC 是 Apple system model 的隐私云扩展；Amsterdam backend 是自有 tenant/artifact/provider/job workflow。不同 ownership、API、modality 和 audit。

Cloud fallback 如何不重复?#

tenant/user scoped idempotency key + canonical request hash + existing job response。

云结果晚到怎么办?#

结果绑定 base asset/recipe/model version。若 current version 已变化，作为 branch，不自动覆盖。

Model rollout?#

Signed immutable artifact→compatibility→smoke→internal cohort→canary→SLO/quality gate→ramp；保留 last-known-good、kill switch、circuit breaker。

如何证明 local-only?#

Router 移除 cloud candidates、transport fail-closed、telemetry egress可关闭、network recorder/integration test验证零 content upload。

最关键的 trace fields?#

request_id/trace_id、operation、workspace pseudonymous scope、asset class/size bucket、model/pre/postprocess、runtime、cache tier、stage latency、peak memory、fallback reason、artifact IDs。

你如何选一个 open-source model?#

先看 product quality，再看 license/training-data policy、Core ML operator compatibility、package/resident/peak memory、cold/warm latency、energy、real-device matrix、update ownership。

Part I — Interview Front Door#

1. 30 秒答案#

I would build a native Edge AI Service Runtime consumed by Photoshop-, Lightroom-, or Acrobat-like clients. The service accepts an asset reference, operation, privacy policy, latency budget, and quality target. Its control plane resolves the model and cache policy, profiles the Apple hardware, and creates an execution plan across Core ML, Vision, MPS, CPU, or cloud fallback. 中文抓手：

native service boundary：app 是 caller，平台暴露稳定 contract。 · edge-first：先端侧完成 cheap / private / latency-sensitive 工作。 · execution plan：不是直接调用某个 model，而是选择 runtime、steps、budget、fallback。 · policy-aware routing：根据 privacy、latency、network、thermal、quality 决定 local/cloud。 · artifact lineage：mask、OCR、embedding、preview、recipe、cloud result 都可复现。 · production telemetry：不仅看 inference，还看 load、queue、pre/postprocess、memory、cache 和 fallback。

2. 两分钟系统设计答案#

我会把系统分成六层：

  1. SDK/API boundary：接收 operation、asset reference、workspace、privacy、latency budget、quality tier；返回同步 result 或 async job handle。
  2. Control plane：Model Registry、Runtime Router、Device Profiler、Cache Policy、feature/config rollout。
  3. Local data plane：ImageIO/PDF engine/AVFoundation decode，Vision/Core ML/MPS inference，postprocess 和 artifact write。
  4. Resource plane：LocalJobQueue、priority/deadline、memory reservation、backpressure、cancellation、failure isolation。
  5. Hybrid plane：CloudFallbackClient 只上传 policy 允许的最小 payload，调用 async backend workflow。
  6. Operations plane：Telemetry、model/runtime/cache lineage、SLO、crash/OOM、rollback、audit 和 cost。

例如 app 请求 subject_mask，service 先计算 asset hash，命中相同 model/preprocess/config 的 mask cache 就直接返回；否则 Runtime Router 根据 device support、ANE availability、memory headroom、thermal state 和 200ms latency budget 选 coreml_ane variant，LocalJobQueue 做资源准入，再执行 decode→inference→refine→atomic artifact write。若 local model 不兼容，只有在 privacy 允许时才走 cloud fallback。

对于 "brighten subject and blur background"，Foundation Models 可以生成 typed edit plan，但真正 pixels side effect 由 deterministic media pipeline 执行。对于高分辨率 generative fill，backend 使用 idempotency key 建 async job，通过 signed URL 上传 crop+mask 等最小 artifact，调用 Photoshop API v2/Firefly，并将结果按 base asset/version 进行 reconciliation。

Part I-A — Native Local Service / SDK Boundary#

5A. 为什么要有 EdgeInferenceService，而不是让每个 feature 直接调 Core ML#

如果 Photoshop、Lightroom、Acrobat 的每个 feature team 都自己加载 model、做 preprocessing、选 compute unit、写 cache 和 fallback，会出现：

同一 model 被重复加载，占用多份 memory。 · preprocessing contract 漂移，造成 silent quality regression。 · 各团队 cache key、privacy 和 telemetry 不一致。 · local/cloud routing 散落在 product code。 · 无法统一做 model rollout、kill switch 和 rollback。 · 高优先级 interactive request 被 background batch 挤压。 · crash/OOM 无法快速归因到 model/runtime/operation。

平台价值：

The EdgeInferenceService centralizes runtime policy and resource ownership while keeping product semantics at the caller.

5H. API/version compatibility#

需要独立 version：

5I. Failure isolation#

In-process#

Swift actor 隔离 mutable state； · operation-specific task； · cancellation handlers； · bounded concurrency； · model load single-flight； · errors 不污染 global cache； · temporary output atomic commit。

XPC/helper process#

crash 后 service restart； · caller 使用 idempotent request/job ID 查询； · dirty temp files 扫描清理； · durable job journal； · model suspected crash loop 时自动 quarantine； · repeated crash 触发 kill switch/fallback。

金句：

A model is an untrusted production artifact from the runtime's perspective. It must be versioned, resource-profiled, health-checked, quarantinable, and rollbackable.

7. History stack：undo/redo 不应该复制整张大图#

弱实现：每次滑动 slider 都保存一张 full-resolution bitmap，memory 和 disk 会迅速爆炸。

Original immutable。 · 每次用户提交操作，append 一个 immutable EditRecipeVersion。 · slider 拖动期间只存在 transient preview state。 · mouse/touch release 后才 commit history entry。 · 定期生成 checkpoint preview，加快长 history 重放。 · cloud result 是 branch，不自动抹掉 local branch。

        └─ v3b cloud enhanced result

这就是 creative workflow 与普通 CRUD 的区别：history 是一个小型 version graph，而不只是最后状态。

8. Image representation 必须会讲#

Bitmap / raster#

由 pixel grid 构成，resolution-dependent。编辑时主要关心：

pixel dimensions； · bit depth； · channel layout； · premultiplied alpha； · row stride； · color space； · orientation metadata。

JPEG#

lossy； · 没有 alpha； · 适合照片 delivery； · 重复 encode 会累积 artifact； · 不适合保存 intermediate edit state。

PNG#

lossless； · 支持 alpha； · UI、mask、graphic 常见； · 照片文件可能大。

HEIF/HEIC#

压缩效率通常比 JPEG 好； · Apple ecosystem 常见； · 可以保存更丰富的 image representation； · interoperability 和 backend decoder support 需要验证。

RAW#

RAW 不是普通 RGB bitmap，而是 sensor data + metadata。典型 pipeline：

text
Sensor mosaic
 -> black-level correction
 -> demosaic
 -> white balance
 -> color transform
 -> tone mapping
 -> noise reduction / sharpening
 -> display/output color space

Lightroom-style non-destructive edit 的本质，是保存 develop parameters，而不是直接改 RAW source。

Alpha channel#

Mask 常用单通道 0...1。合成公式：

text
output = foreground * mask + background * (1 - mask)

实际工程要注意：

straight alpha vs premultiplied alpha； · mask edge feather； · mask 分辨率与 image extent； · blur 后 extent 变大； · orientation 是否已 baked into pixels。

Color spaces#

至少会区分：

sRGB：普遍 delivery/display baseline。 · Display P3：更宽 gamut，Apple displays 常见。 · linear RGB：很多 blend、blur、lighting computation 更适合在线性空间完成。 · working color space vs output color space。 · ICC profile 必须保留或明确转换。

高级回答：

I would avoid silently treating every image as sRGB. Import preserves the embedded profile, rendering uses an explicit working space, and export applies a deliberate output transform. Mask generation may use a normalized model input, but the creative render path must preserve the user-visible color pipeline.

HDR#

HDR 不只是“更亮”，而是更大的 luminance/dynamic range 和不同 transfer function。需要考虑：

extended-range pixel formats； · EDR display； · tone mapping； · SDR fallback； · cloud API 是否保留 HDR metadata； · preview 和 export 是否一致。

Part III — Core ML Deployment Runtime#

9. .mlmodel、.mlpackage、compiled model#

.mlmodel#

单文件 Core ML model representation，适合较传统的 model format。加入 Xcode target 后通常由 build system 编译。

.mlpackage#

目录式 package，可把 model structure、weights、metadata 分开。ML Program 需要 package format，Core ML Tools 7+ 的转换默认倾向生成 mlprogram；它通常保存为 .mlpackage。

Compiled model#

设备执行时使用 compiled representation。工程上关注：

首次 preparation/cold load 成本； · app-bundled model vs downloaded model； · model checksum 和 signature； · OS/runtime compatibility； · failed update 后保留 last-known-good model。

不要说 .mlpackage 天然比 .mlmodel 快。它们是 packaging/model representation 问题，真实 latency 要 benchmark。

10. Model loading#

不要在 main thread 同步做大模型 loading。

swift
import CoreML

actor SegmentationModelStore {
    private var cached: MLModel?
    private var identity: ModelIdentity?

    func load(
        from compiledURL: URL,
        identity requestedIdentity: ModelIdentity,
        computeUnits: MLComputeUnits
    ) throws -> MLModel {
        if identity == requestedIdentity, let cached {
            return cached
        }

        let config = MLModelConfiguration()
        config.computeUnits = computeUnits

        let model = try MLModel(
            contentsOf: compiledURL,
            configuration: config
        )

        cached = model
        identity = requestedIdentity
        return model
    }

    func evict() {
        cached = nil
        identity = nil
    }
}

Production improvements：

background actor/task loading； · duplicate load suppression； · warmup request； · load timeout； · memory-pressure eviction； · model update validation； · last-known-good fallback。

11. CPU / GPU / Neural Engine#

MLModelConfiguration.computeUnits 常见选择：

.cpuOnly：debug、determinism investigation、unsupported accelerator fallback。 · .cpuAndGPU：允许 CPU/GPU，不用 ANE。 · .cpuAndNeuralEngine：允许 CPU/ANE，不用 GPU。 · .all：允许 Core ML 自行使用可用 compute units。

关键认知：指定 .all 不表示整个 graph 一定跑在 ANE。operator support、shape、precision、memory 和 runtime planner 会影响 placement，graph 也可能分段执行。

面试不要回答“ANE 永远最快”。正确回答：

I benchmark the actual model on the target device family. ANE can be excellent for supported neural operators and energy efficiency, GPU can be better for some tensor or image workloads, and CPU remains important for preprocessing, small models, control logic, and fallback. End-to-end latency includes copies and preprocessing, not just kernel time.

Interactive editor 通常优先 single inference：

Batch 适合：

Lightroom catalog background indexing； · 批量 thumbnail tagging； · offline embedding； · photo library maintenance。

17. Memory pressure handling#

图片编辑很容易同时持有：

  • original compressed bytes；
  • decoded full-resolution bitmap；
  • smart preview；
  • model weights；
  • input/output pixel buffers；
  • masks；
  • multiple GPU textures；
  • history thumbnails；
  • cloud result。

策略：

  • preview 用降采样，不先 decode full resolution；
  • reuse CVPixelBufferPool / texture pool；
  • 避免 CPU bitmap 与 GPU texture 反复 copy；
  • intermediate texture 设置合适 storage mode；
  • cache 设 byte budget，不只设 item count；
  • 收到 memory warning 时先删 derived artifacts；
  • model 可重载时允许 eviction；
  • full-resolution export 采用 tile/chunk pipeline；
  • autorelease pool 包住批量处理。

优先级：

text
Never evict:
  original reference + committed recipe + user-visible unsaved state

Evict first:
  recomputable thumbnails -> old masks -> intermediate renders
  -> inactive model -> full-resolution decoded buffer

18. Vision request pipeline#

Vision 的价值是提供统一 request/observation abstraction、orientation handling、Core ML integration 和系统算法。

典型流程：

swift
import Vision
import CoreML

func segment(
    cgImage: CGImage,
    orientation: CGImagePropertyOrientation,
    coreMLModel: MLModel
) throws -> CVPixelBuffer {
    let visionModel = try VNCoreMLModel(for: coreMLModel)
    let request = VNCoreMLRequest(model: visionModel)
    request.imageCropAndScaleOption = .scaleFit

    let handler = VNImageRequestHandler(
        cgImage: cgImage,
        orientation: orientation,
        options: [:]
    )
    try handler.perform([request])

    // Exact observation type depends on the model's declared output.
    if let pixelObservation = request.results?.first as? VNPixelBufferObservation {
        return pixelObservation.pixelBuffer
    }

    if let featureObservation =
        request.results?.first as? VNCoreMLFeatureValueObservation,
       let array = featureObservation.featureValue.multiArrayValue {
        return try convertMaskArrayToPixelBuffer(array)
    }

    throw SegmentationError.unexpectedOutput
}

代码中的关键点：

func validate(_ plan: CreativeEditPlan) throws -> EditRecipe {
    guard plan.operations.count <= 8 else {
        throw PlanError.tooManyOperations
    }

    let operations = try plan.operations.map { op -> EditOperation in
        switch (op.kind, op.target) {
        case ("exposure", "subject"):
            return .exposure(
                target: .subject,
                ev: Float(op.amount.clamped(to: -2.0...2.0))

                target: .background,
                radius: Float(op.amount.clamped(to: 0.0...30.0))

            throw PlanError.unsupportedOperation

Part VI — Core Image, Metal, MPS, MPSGraph#

32. 如何选择 Core Image、MPS、Metal、MPSGraph#

Technology最适合不要误用
Core Imagefilter graph、color adjustment、compositing、快速 non-destructive preview不适合表达任意复杂 ML graph
Metalcustom GPU compute/render、精确控制 texture/buffer、最高性能路径成本高，简单 filter 不必手写 shader
Metal Performance Shaders高性能 image/math kernels，例如 blur、convolution、morphology不是完整 creative document model
MPSGraphtensor/compute graph、linear algebra、ML/CV computationUI image filter 能用 Core Image 时不必强上
Accelerate/vImageCPU vector/image processing、fallback、小型 preprocessing大型实时 GPU pipeline 可能不够

面试回答：

I start with Core Image because it provides a lazy, composable image-processing graph and integrates well with Metal-backed rendering. I move specific bottlenecks to MPS or custom Metal kernels only after profiling. MPSGraph is useful when the operation is naturally a multidimensional tensor graph rather than a conventional image filter.

33. Core Image non-destructive render graph#

Core Image 常适合 prototype 和 production preview：

swift
import CoreImage

struct CreativeRenderer {
    let context: CIContext

    func render(
        source: CIImage,
        subjectMask: CIImage,
        subjectEV: Float,
        backgroundBlur: Float
    ) -> CIImage {
        let adjustedSubject = source.applyingFilter(
            "CIExposureAdjust",
            parameters: [kCIInputEVKey: subjectEV]
        )

        let blurredBackground = source
            .clampedToExtent()
            .applyingFilter(
                "CIGaussianBlur",
                parameters: [kCIInputRadiusKey: backgroundBlur]
            )
            .cropped(to: source.extent)

        let subjectComposite = adjustedSubject.applyingFilter(
            "CIBlendWithMask",
            parameters: [
                kCIInputBackgroundImageKey: blurredBackground,
                kCIInputMaskImageKey: subjectMask
            ]
        )

        return subjectComposite.cropped(to: source.extent)
    }
}

注意：

CIGaussianBlur 会扩大 extent，要 clamp/crop。 · Mask 黑白方向要确认：白色通常选择 input image，黑色选择 background。 · CIContext 应复用，不要每帧创建。 · Working color space 和 output color space 要显式。 · 拖 slider 时使用 preview resolution；export 再用 full resolution。

34. Metal mental model#

Texture#

MTLTexture 是适合 GPU image access 的资源，包含：

width/height/depth； · pixel format； · mip levels； · usage； · storage mode。

Image editing 更常用 texture，因为 GPU 可以按二维坐标采样、过滤和写入。

Buffer#

MTLBuffer 是线性 memory，可用于：

parameters； · vertices； · tensor data； · lookup tables； · indirect arguments。

Command queue / command buffer#

text
MTLDevice
  -> MTLCommandQueue
      -> MTLCommandBuffer
          -> Compute/Render/Blit Encoder
              -> encode commands
          -> commit

Command queue 应长期复用。每个 frame/job 创建 command buffer，encode 后 commit。不要为了每个小 operation 都等待 GPU 完成；尽量把相关 kernels 合并到一个合理的 command submission。

35. Minimal Metal compute kernel#

下面是概念性 background exposure kernel：

metal
#include <metal_stdlib>
using namespace metal;

kernel void maskedExposure(
    texture2d<float, access::read> source [[texture(0)]],
    texture2d<float, access::read> mask [[texture(1)]],
    texture2d<float, access::write> output [[texture(2)]],
    constant float &gain [[buffer(0)]],
    uint2 gid [[thread_position_in_grid]]
) {
    if (gid.x >= output.get_width() || gid.y >= output.get_height()) {
        return;
    }

    float4 pixel = source.read(gid);
    float m = mask.read(gid).r;
    float3 adjusted = pixel.rgb * gain;
    output.write(float4(mix(pixel.rgb, adjusted, m), pixel.a), gid);
}

真正 production 要继续考虑：

  • linear color space；
  • half precision；
  • threadgroup sizing；
  • texture format；
  • alpha；
  • bounds；
  • in-place safety；
  • resource reuse；
  • kernel fusion。

36. MPS image processing#

Amsterdam-style editor 可用 MPS：

MPSImageGaussianBlur：背景 blur； · convolution：sharpen、edge； · morphology：mask dilate/erode； · image pyramid：multiscale preview/refinement； · matrix/math kernels：部分 tensor transform。

MPS 的价值是避免自己维护所有 optimized kernels，但仍需要管理 Metal resources 和 command buffers。

37. MPSGraph#

MPSGraph 适合把 tensor computation 表达成 graph：

text

 -> normalize
 -> matrix/convolution ops

 -> output tensor

它可以利用平台不同 compute devices。面试要强调 graph compile/execution、shape、data type、memory、operator compatibility 和 profiling，而不是只说“它能跑神经网络”。

Core ML vs MPSGraph：

已有可转换 model，优先 Core ML 获得系统级 deployment/runtime optimization。 · 自定义 tensor graph、research operation、模型外 preprocessing/postprocessing，可考虑 MPSGraph。 · 不要复制 Core ML 已经做好的 model scheduling。

40. ONNX 什么时候有价值#

ONNX 可作为 cross-runtime interchange format，用于：

41. Operator compatibility#

转换前检查：

  • unsupported custom ops；
  • dynamic control flow；
  • dynamic shapes；
  • unusual resize/interpolation；
  • grid sampling；
  • normalization；
  • attention variants；
  • custom postprocess；
  • stateful operations。

处理策略：

  1. 用等价 supported op 重写。
  2. 把 preprocessing/postprocessing 移到 Swift/Metal。
  3. 分割 model graph。
  4. custom layer 是最后手段，因为增加 deployment/maintenance cost。
  5. 若 fallback 到 CPU，要确认 latency 和 energy 是否仍满足 SLO。

面试强句：

Conversion success is not deployment success. I validate numerical parity, operator placement, memory, cold load, warm latency, and quality on the actual device matrix.

42. Quantization#

FP16#

每个值 16 bit； · 通常是 edge deployment 的低风险起点； · 减少 model size/bandwidth； · accuracy loss 往往较小，但仍需 eval。

INT8#

更小、更省 bandwidth； · weight-only 或 weight+activation； · activation quantization 通常需要 calibration； · 对 boundary-sensitive segmentation 要特别检查 edge quality。

INT4#

压缩更激进； · model/runtime/operator support 更关键； · quality drop 风险更高； · 适合大模型 weight compression 的讨论，但不能假设所有 CV model 都更快。

关键认知：

text
smaller model != automatically lower latency

如果 runtime 需要 dequantize、operator 不加速、memory copy 占主导，文件变小但 latency 不一定下降。

50. Routing policy#

swift
enum ExecutionMode {
    case local
    case hybrid
    case cloud
    case unavailable(reason: String)
}

struct RuntimeContext {
    let localModelAvailable: Bool
    let foundationModelAvailable: Bool
    let thermalState: ProcessInfo.ThermalState
    let lowPowerMode: Bool
    let networkReachable: Bool
    let networkConstrained: Bool
    let memoryHeadroomMB: Int
    let privacyAllowsCloud: Bool
    let requiresGenerativeEdit: Bool
    let localCacheHit: Bool
}

func chooseMode(_ c: RuntimeContext) -> ExecutionMode {
    if !c.privacyAllowsCloud {
        return c.localModelAvailable
            ? .local
            : .unavailable(reason: "Cloud processing is disallowed by policy")
    }

    if c.requiresGenerativeEdit {
        guard c.networkReachable else {
            return .unavailable(reason: "Generative enhancement requires network")
        }
        return c.localModelAvailable ? .hybrid : .cloud
    }

    if c.localCacheHit {
        return .local
    }

    if c.thermalState == .serious || c.thermalState == .critical {
        return c.networkReachable ? .cloud : .local
    }

    if c.lowPowerMode && c.networkReachable && !c.networkConstrained {
        return .cloud
    }

    return c.localModelAvailable ? .local : .cloud
}

这只是 readable policy baseline。成熟系统会把 thresholds/version 放在 signed experiment config 中，并记录每次 decision reason。

54F. Deadline-aware scheduling#

基础策略：

  • priority queue 按 priority class + deadline + enqueue time。
  • interactive 使用 Earliest Deadline First 的思想。
  • background 加 aging，防止永远饥饿。
  • stale request 在执行前取消，例如用户已经翻到另一个 PDF page。
  • 不能安全 preempt 的 GPU/ANE inference，不要假装支持 kernel-level 抢占；可在 job boundary/cancellable stages 控制。

Pseudocode：

python
def score(job, now):
    deadline_urgency = 1.0 / max(job.deadline - now, 0.001)
    aging = min((now - job.enqueued_at) / 30.0, 5.0)
    return (
        PRIORITY_WEIGHT[job.priority]
        + deadline_urgency
        + aging
        - job.estimated_memory_mb * MEMORY_PENALTY
    )

def select_next(queue, resources, context):
    candidates = [
        job for job in queue
        if job.policy_allows(context)
        and resources.can_reserve(job.profile)
        and not job.is_stale()
    ]
    return max(candidates, key=lambda j: score(j, now())) if candidates else None

按 (model_version, runtime, device_family, OS) 维护 health：

consecutive load failures； · crash signature； · OOM； · timeout； · invalid output； · checksum/corruption。

状态：

text
CLOSED -> OPEN -> HALF_OPEN -> CLOSED

Open 后：

停止选择该 variant/runtime； · fallback previous model； · 上传 privacy-safe failure metadata； · 等 cooldown 后少量 probe； · remote config 可 kill switch。

54L. Scheduler interview answer#

I would not expose Core ML directly to every feature. The local gateway performs admission and deadline-aware scheduling, reserves memory based on model and tensor profiles, coalesces duplicate work, batches only background-compatible requests, and uses circuit breakers for unhealthy model/runtime combinations. Interactive work wins over catalog indexing, but background jobs use aging and charging/thermal policies so they eventually make progress.

57E. Storage tiers#

text
Tier 0: active GPU/Metal resources
  fastest, smallest, process/session lifetime

Tier 1: process memory
  decoded preview, hot mask, hot embedding

Tier 2: local persistent metadata + files
  SQLite index + content-addressed artifact files

Tier 3: desktop/server local KV store
  RocksDB-like engine when write/read scale justifies it

Tier 4: cloud object/artifact store
  cross-device sync, expensive result, backup if policy permits

Memory#

适合：

tiny/hot； · session reuse； · lowest latency。

缺点：memory pressure、process death、sensitive lifetime。

SQLite#

适合：

metadata index； · transactional state； · lookup by key/workspace/type/version； · LRU timestamps； · mobile/desktop built-in operational simplicity。

不要把大 image/PDF blob 默认塞 SQLite；保存 file path、checksum、size、metadata。

File store#

适合：

masks； · previews； · page images； · model files； · OCR JSON； · large tensors。

需要：

temp + atomic rename； · checksum； · directory sharding； · quota； · cleanup journal； · backup exclusion； · file protection/encryption。

RocksDB#

适合：

macOS helper/backend； · very high-throughput key/value metadata or chunk index； · LSM-tree workload； · custom compaction/prefix scan。

不一定适合 iOS 默认方案：

binary/operational footprint； · compaction write amplification； · memory tuning； · lifecycle/sandbox complexity； · SQLite + file store 往往更简单。

Cloud tier#

只用于 policy 允许：

expensive-to-recompute artifact； · cross-device； · team collaboration； · durable cloud job output。

Cloud hit 仍有 network latency；router 要把它视作一个 execution path，不是“免费 cache”。

57H. LRU、LFU、TTL 不够#

LRU#

最近使用优先保留。适合 interactive working set。

高频保留，但会被历史热点污染。

TTL#

适合：

Cost-aware eviction#

更适合 edge AI：

text
value(entry) =
  estimated_recompute_ms
  * expected_reuse_probability
  * privacy/locality_bonus

例如：

5MB、需 800ms 重新 OCR 的 page，比 20MB、10ms 生成的 thumbnail 更值得保留。 · cloud-only result 在 offline 场景 value 更高。 · stale model version 即使常用，也应被 rollout policy 驱逐。

太大：partial reuse 差、eviction 粗、read amplification。 · 太小：metadata 爆炸、open/read overhead、fragmentation。

64. Polling vs webhook#

Polling#

Client/backend 定时查 status。

优点：简单、适合 prototype。

缺点：额外 QPS、更新不实时。

策略：exponential backoff + jitter，前台快、后台慢，terminal state 停止。

Webhook#

Provider 回调 backend。

需要：

signature verification； · replay protection； · idempotent handler； · event ordering； · DLQ； · webhook 丢失后 polling reconciliation。

Production 通常 webhook + periodic reconciliation，而不是二选一。

65. Retry / timeout / cancellation#

不同 stage 不同 timeout：

token request：短； · upload：按 size/network； · job submit：短； · provider processing：长 async deadline； · result download：按 size。

Retry：

429 尊重 Retry-After； · retryable 5xx 用 exponential backoff + jitter； · 限制 attempts； · circuit breaker； · deadline propagation； · cancel 要传递到 queued/running provider job（若 provider 支持）。

Amsterdam Photoshop technical notes 建议只对合适的 server errors 重试，并对 429 使用 provider 指示。具体 policy 以 v2 最新文档和 endpoint contract 为准。

每个 request 必须带：

76Q. PDF interview answer#

I design document AI as a page- and block-oriented artifact pipeline, not as extractText(pdf). import hashlib

def sha256_file(path: Path, chunk_size: int = 1024 * 1024) -> str:
    digest = hashlib.sha256()
    with path.open("rb") as source:
        while chunk := source.read(chunk_size):
            digest.update(chunk)
    return digest.hexdigest()


def canonical_json_hash(value: dict[str, Any]) -> str:
    encoded = json.dumps(
        value,
        sort_keys=True,
        separators=(",", ":"),
        ensure_ascii=False,
    ).encode("utf-8")
    return hashlib.sha256(encoded).hexdigest()

Python 10. Atomic artifact store#

python
import os
import tempfile
from dataclasses import dataclass
from pathlib import Path


@dataclass(frozen=True, slots=True)
class StoredArtifact:
    path: Path
    sha256: str
    size_bytes: int


class ArtifactStore:
    def __init__(self, root: Path) -> None:
        self.root = root
        self.root.mkdir(parents=True, exist_ok=True)

    def _content_path(self, sha256: str, suffix: str) -> Path:
        return self.root / sha256[:2] / sha256[2:4] / f"{sha256}{suffix}"

    def put_bytes(self, data: bytes, *, suffix: str) -> StoredArtifact:
        sha256 = hashlib.sha256(data).hexdigest()
        destination = self._content_path(sha256, suffix)
        destination.parent.mkdir(parents=True, exist_ok=True)

        if destination.exists():
            return StoredArtifact(destination, sha256, destination.stat().st_size)

        file_descriptor, temporary_name = tempfile.mkstemp(
            dir=destination.parent,
            prefix=".writing-",
        )
        temporary = Path(temporary_name)

        try:
            with os.fdopen(file_descriptor, "wb") as target:
                target.write(data)
                target.flush()
                os.fsync(target.fileno())
            os.replace(temporary, destination)
        finally:
            temporary.unlink(missing_ok=True)

        return StoredArtifact(destination, sha256, len(data))

生产改进：

大文件使用 streaming put_file，不要 read_bytes()。 · metadata DB transaction 在 file commit 后标记 READY。 · workspace encryption 可在 write stream 上完成。 · orphan temp file 用 startup recovery/TTL 清理。 · os.replace 提供同 filesystem 的 atomic rename。

Python 12. Single-flight duplicate suppression#

同一 asset/mask request 被多个 feature 同时请求时，只执行一次：

python
import asyncio
from collections.abc import Awaitable, Callable
from typing import TypeVar

T = TypeVar("T")


class SingleFlight:
    def __init__(self) -> None:
        self._lock = asyncio.Lock()
        self._tasks: dict[str, asyncio.Task[object]] = {}

    async def run(self, key: str, factory: Callable[[], Awaitable[T]]) -> T:
        async with self._lock:
            task = self._tasks.get(key)
            if task is None:
                task = asyncio.create_task(factory())
                self._tasks[key] = task

        try:
            return await task  # type: ignore[return-value]
        finally:
            if task.done():
                async with self._lock:
                    if self._tasks.get(key) is task:
                        self._tasks.pop(key, None)

注意：

一个 waiter cancel 时，不一定要 cancel shared task。 · Production 可用 asyncio.shield(task) 防止 caller cancellation 传播给 shared work。 · Failed task 必须从 map 移除，不能永久缓存 exception。

Python 13. Async memory budget#

import asyncio
from contextlib import asynccontextmanager


class MemoryBudget:
    def __init__(self, total_mb: int) -> None:
        self.total_mb = total_mb
        self.available_mb = total_mb
        self._condition = asyncio.Condition()

    @asynccontextmanager
    async def reserve(self, requested_mb: int):
        if requested_mb > self.total_mb:
            raise EdgeAIError(
                ErrorCode.MEMORY_ADMISSION_REJECTED,
                f"request {requested_mb} MB exceeds total budget",
            )

        async with self._condition:
            await self._condition.wait_for(
                lambda: self.available_mb >= requested_mb
            )
            self.available_mb -= requested_mb

        try:
            yield
        finally:
            async with self._condition:
                self.available_mb += requested_mb
                self._condition.notify_all()

Python 14. Deadline-aware priority queue#

python
import asyncio
import itertools
import time
from dataclasses import dataclass, field
from typing import Any


@dataclass(order=True, slots=True)
class ScheduledJob:
    sort_key: tuple[float, float, int]
    job_id: str = field(compare=False)
    request: EdgeRequest = field(compare=False)
    estimated_memory_mb: int = field(compare=False)
    future: asyncio.Future[Any] = field(compare=False)


class LocalScheduler:
    def __init__(self, memory_budget: MemoryBudget) -> None:
        self.queue: asyncio.PriorityQueue[ScheduledJob] = asyncio.PriorityQueue()
        self.memory_budget = memory_budget
        self._sequence = itertools.count()

    def _sort_key(self, request: EdgeRequest) -> tuple[float, float, int]:
        priority = {
            "fast": 0,
            "balanced": 1,
            "high": 2,
        }[request.quality_tier]
        deadline = (
            request.deadline.timestamp()
            if request.deadline is not None
            else time.time() + request.latency_budget_ms / 1000
        )
        return priority, deadline, next(self._sequence)

    async def submit(
        self,
        request: EdgeRequest,
        *,
        estimated_memory_mb: int,
    ) -> Any:
        future = asyncio.get_running_loop().create_future()
        job = ScheduledJob(
            sort_key=self._sort_key(request),
            job_id=str(request.request_id),
            request=request,
            estimated_memory_mb=estimated_memory_mb,
            future=future,
        )
        await self.queue.put(job)
        return await future

    async def worker(self, execute) -> None:
        while True:
            job = await self.queue.get()
            try:
                if job.future.cancelled():
                    continue

                timeout_seconds = job.request.latency_budget_ms / 1000
                async with asyncio.timeout(timeout_seconds):
                    async with self.memory_budget.reserve(
                        job.estimated_memory_mb
                    ):
                        result = await execute(job.request)
                job.future.set_result(result)
            except Exception as exc:
                if not job.future.done():
                    job.future.set_exception(exc)
            finally:
                self.queue.task_done()

代码简化点：

quality_tier 不应直接等同 priority；production 应有独立 workload_class。 · Timeout 要减去已经花费的 admission/queue time。 · Scheduler 应支持 queue limits、aging、latest-wins 和 graceful shutdown。

        request: EdgeRequest,
        context: DeviceContext,
        variants: list[ModelVariant],
    ) -> ExecutionChoice:
        eligible = [
            variant
            for variant in variants
            if variant.estimated_peak_memory_mb <= context.memory_headroom_mb
        ]

        if context.thermal_state == "critical":
            eligible = [
                variant for variant in eligible
                if variant.estimated_peak_memory_mb <= 128
            ]

        for runtime in ("coreml_ane", "coreml_gpu", "coreml_cpu"):
            if runtime == "coreml_ane" and not context.ane_available:
                continue
            if runtime == "coreml_gpu" and not context.gpu_available:
                continue

            candidates = [
                variant for variant in eligible
                if runtime in variant.supported_runtimes
            ]
            if candidates:
                chosen = min(candidates, key=lambda item: item.warm_p95_ms)
                return ExecutionChoice(runtime, chosen, "local_slo_candidate")

        if request.privacy is PrivacyMode.LOCAL_ONLY:
            raise EdgeAIError(
                ErrorCode.PRIVACY_POLICY_BLOCKED,
                "no eligible local runtime and cloud is forbidden",
            )

        if context.network_available:
            return ExecutionChoice("cloud", None, "no_eligible_local_variant")

        raise EdgeAIError(
            ErrorCode.MODEL_UNAVAILABLE,
            "no eligible local runtime and network unavailable",
        )

Production router 不应只用 first-match：

quality score； · predicted latency； · cache locality； · energy/thermal； · cloud cost； · runtime health/circuit breaker； · provider policy。

Part XV — Interview Q&A#

95. 为什么端侧优先，不是全部上云？#

因为 creative assets 大、私密、交互频繁。端侧能降低 first-preview latency、bandwidth 和 privacy exposure，并支持 offline。云端仍适合大型 generative model 和高质量 final processing。最佳设计不是 local-only，而是按 task boundary 做 hybrid。

96. 为什么不把所有任务都放到 ANE？#

ANE 是否使用取决于 operator、shape、precision 和 runtime support。部分 graph 可能落 CPU/GPU。Image decode、control logic、custom render 也不属于纯 neural inference。应该在 target device 上 profile total latency/energy，而不是硬编码“ANE always fastest”。

97. Core ML 和 Vision 的区别？#

Core ML 是 model deployment/inference runtime；Vision 是 computer-vision request pipeline 和系统算法，并能包装 Core ML model。Vision 帮助处理 image requests、orientation 和 observations，但 model execution 仍可由 Core ML 完成。

98. Core Image 和 Metal 的区别？#

Core Image 是高层、lazy、可组合 filter graph，适合多数 image adjustment/compositing。Metal 提供底层 GPU resource 和 shader control。先用 Core Image，profile 后将真正 bottleneck 移到 MPS/custom Metal。

99. 如何实现 “brighten subject and blur background”？#

  1. Vision/Core ML 产生 subject mask。
  2. Foundation Models 生成 typed operations。
  3. Validator 限制 exposure/blur range。
  4. Core Image 对 source 生成 exposure branch 和 blur branch。
  5. 用 subject mask blend。
  6. 保存 recipe，不改 original。
  7. preview 用低分辨率，export 在 full resolution 重放。

100. Model output 为什么在 iPhone 上质量变差？#

排查顺序：

  • preprocessing 是否一致；
  • orientation/crop；
  • RGB/BGR；
  • scale/bias；
  • FP16/INT8 numerical change；
  • unsupported/fallback op；
  • output activation/threshold；
  • resize interpolation；
  • mask transform；
  • 真实 domain dataset。

不要第一反应就是“Core ML 不准”。

101. 如何处理 memory pressure？#

先保护 original reference、committed recipe 和 unsaved state；删除可重建 preview/intermediate；降低 preview resolution；reuse pixel/texture pools；evict inactive model；full-resolution export tiled；收到 warning 后停止 background inference。

102. Quantization 如何判断成功？#

不是文件变小就成功。要同时看：

domain quality； · boundary quality； · warm/cold latency； · peak memory； · energy/thermal； · real device； · fallback/operator placement； · crash stability。

103. LLM tool calling 如何保证安全？#

LLM 只选择允许工具并生成 typed arguments。执行前 deterministic validation、authorization、range limit、idempotency、confirmation。Tool 使用 scoped capability，所有 state transition 可审计和回滚。

104. Cloud 结果回来时用户已经继续编辑怎么办？#

Cloud job 绑定 base recipe/mask/source checksum。返回后如果 current version 不同，就作为 branch，显示 compare/rebase 选项，不能 silently overwrite。

105. 如何设计 cache key？#

任何会改变 output/correctness/security scope 的东西进入 key：source checksum、model/version、preprocess、recipe、mask、renderer、size、color space、tenant。Cache 是 correctness contract，不只是性能技巧。

106. 如何测端侧 latency？#

拆 admission、queue、decode、preprocess、load、inference、postprocess、artifact commit 和 response；区分 cold/warm；按 device/OS/compute/model 分桶；报告 p50/p95，不只平均值；用 signpost/Instruments，并测 physical device。

107. 为什么 async cloud job？#

Generative media latency 长尾明显，需要 progress、cancel、retry、webhook/poll、client disconnect recovery。同步 HTTP 无法很好表达 durable workflow。

108. 为什么 Photoshop API v2？#

Photoshop API v1 的 end-of-life 是 2026-07-31。新项目直接围绕 v2 contract 和 migration-safe provider adapter 设计，避免把 deprecated contract 散落在 mobile/backend code。

109. RAW 和普通 JPEG 编辑有什么不同？#

RAW 是 sensor-domain data，需要 develop pipeline；JPEG 已是 processed lossy RGB。Lightroom-style edit 保存 develop parameters，并根据 RAW/color pipeline 重放；JPEG editing 的可恢复信息和 dynamic range 更少。

110. 如何支持 PDF？#

PDFKit 做 viewing/search/annotation，Core Graphics 做低层 render/create，Vision OCR 处理 scanned pages。大 PDF 按 page/lazy render，不一次 rasterize。真正 redaction 必须移除 content，不只是画 overlay。Enterprise forms/redaction/conversion 可评估 Nutrient/Apryse。

111. 什么时候使用 Create ML？#

快速训练 product-specific 小分类器/检测器时，例如 edit intent triage 或 image category。复杂 segmentation/transformer 仍可在 PyTorch 训练，然后 Core ML Tools 转换。

112. 端侧 telemetry 会不会破坏 privacy？#

只记录 operational metadata：model version、duration、memory、cache、error、coarse device class。Asset/prompt 默认不上传；ID hash/scope；debug trace 受控、redacted、有 retention。

113. 本地模型如何更新？#

Signed manifest、download temp、checksum/signature、OS/input compatibility、smoke inference、atomic activate、canary、last-known-good rollback。Model artifact immutable，不覆盖 latest。

114. 你会选择 SwiftData 还是 Core Data？#

取决于 deployment target、schema complexity、migration/history 和 team maturity。Prototype 可用 SwiftData；复杂 catalog/history 或已有成熟 stack 可用 Core Data/SQLite。大 binary 不直接进 DB。

115. 如果网络很差怎么办？#

local preview 和 manual edit 不受影响；cloud enhancement 明确 pending/disabled；上传最小 payload；background transfer；exponential backoff；idempotency；用户可取消；不让 spinner 永久转。

115A. 为什么需要 local service/API boundary？#

为了统一 model loading、preprocessing、cache、runtime routing、resource scheduling、privacy、telemetry 和 rollout。否则每个 product feature 都会复制一套逻辑，并造成多份 model memory、质量漂移和不可运营的 fallback。

115B. iOS 上能不能做常驻 daemon？#

不应该以任意常驻 daemon 为设计假设。iOS 通常使用 in-process framework/actors，并遵守 app/background lifecycle。macOS 可以评估 XPC/helper process 做 crash/privilege isolation。API contract 可以一致，但 deployment topology 不同。

115C. Runtime Router 和 Scheduler 有什么区别？#

Router 决定 eligible execution path 和 model/runtime；Scheduler 在资源和 deadline 约束下决定什么时候执行。Router 处理 policy/placement，Scheduler 处理 queue、priority、memory reservation、batching、backpressure 和 cancellation。

115D. 如何防止一个 100MP image job 把 runtime 弄崩？#

  • admission 读取 dimensions/format；
  • estimated decoded bytes；
  • preview/downsample fast path；
  • tile processing；
  • memory token reservation；
  • bounded concurrency；
  • intermediate reuse/eviction；
  • timeout/cancel；
  • unsafe size reject；
  • XPC/worker isolation where available。

115E. 为什么 model registry 需要 memory 和 warmup profile？#

Router 不能只知道 model ID。它需要 peak memory、load time、input shapes、batchability、supported OS/runtime、quality tier、operator compatibility 和 fallback，才能在 200ms budget 或 low-memory device 上做正确选择。

115F. 如何处理 local model crash loop？#

按 model/runtime/device/OS 维护 circuit breaker。连续 crash/load failure 后 quarantine variant，fallback previous model/runtime，remote kill switch，保留 privacy-safe crash signature，cooldown 后 half-open probe。

115G. 什么时候使用 local batching？#

同 model、同 shape、loose deadline 的 background embedding/OCR/tagging。Interactive mask 不应为了 throughput 等 batching window。Batch key 还应考虑 model/config 和 workspace/privacy compatibility。

115H. Edge Cache 为什么需要 workspace salt？#

单纯 content hash 会让不同 workspace 的相同 private file 映射到同一个 key，产生信息泄漏或错误共享。Workspace salt/namespace 让 cache identity 同时表达 content 和 security scope。

115I. SQLite 和 RocksDB 怎么选？#

Apple client 端优先 SQLite metadata + file artifact store，部署简单、transaction 清晰。RocksDB 更适合 macOS helper/backend 的高吞吐 LSM/KV workload，但要承担 compaction、memory、binary 和 lifecycle tuning。不要因为“规模大”就默认 RocksDB。

115J. PDF 为什么不能直接统一 OCR？#

Native text page 的原始 text/coordinates 通常更准确、更快。无差别 OCR 增加 latency/cost，还可能把已有文字识别错。应先 page classification，native extraction fast path，只有 scanned/low-quality page 才 raster+OCR。

115K. PDF semantic chunking 如何支持 citations？#

每个 chunk 保存 document version、page、bbox、source block、heading path、parser/OCR/chunker version。RAG answer 可回到精确 page/region，不只是引用一段脱离版面的文本。

115L. 如何设计 local-only 的可证明性？#

Router hard constraint 去除 cloud candidate；network client 对该 request context fail closed；telemetry 可关闭 egress；integration test 通过 mock network recorder 验证零上传；audit 记录 policy decision，但不记录 raw content。

115M. Private Cloud Compute 与自建 cloud fallback 有什么区别？#

PCC 是 Apple system foundation-model capability 的隐私云扩展概念；自建 fallback 是 product/backend 自己管理的 provider、artifact、tenant、cost 和 audit workflow。两者都要经过 policy，但 ownership、modality、API 和 operational control 不同。

115N. 如何定义 edge runtime 的成功，而不只是 inference 快？#

看 end-to-end SLO、OOM/crash、cache latency saved、fallback correctness、battery/thermal、artifact success、cloud escalation/cost、用户任务结果。Model kernel 快但 queue 长、memory 爆、cache 错或 cloud 泄露，runtime 仍然失败。

131. Five senior-level sentences#

  1. Edge AI is not moving a cloud model onto a phone; it is building a policy- and resource-aware execution platform under privacy, latency, memory, thermal, and offline constraints.
  2. The client owns product semantics, while the EdgeInferenceService owns execution planning, model/runtime selection, caching, scheduling, failure isolation, and telemetry.
  3. Conversion success is not deployment success; I validate numerical parity, operator placement, cold load, warm latency, memory, and domain quality on real devices.
  4. A cache key is part of the correctness and security model, so asset, workspace, model, preprocessing, and output schema all participate in identity.
  5. The local path optimizes privacy and latency, the cloud path handles expensive quality, and one versioned artifact lineage connects both.

132. Common weak answers to avoid#

弱：

I use Core ML because it is fast.

强：

I use Core ML for system-integrated on-device deployment, but I benchmark model-specific CPU/GPU/ANE behavior, including preprocessing, copies, cold load, memory, and quality.

弱：

I call Firefly if local fails.

强：

The router escalates only when policy permits and local capability cannot satisfy the quality requirement; it uploads minimal artifacts through an idempotent async job and records the fallback reason.

弱：

The LLM edits the image.

强：

The LLM emits a guided, typed plan. Deterministic, authorized tools validate and execute the edit non-destructively.

弱：

We cache the result.

强：

Cache keys include source checksum, tenant scope, model, preprocessing, mask, recipe, renderer, output size, and color space so a hit is also correct.
