4. Flagship System Design：AI Native Multimodal Asset & Workflow Platform#

这是最重要的一题。目标是同时覆盖 Asset Services、AIGC、Agentic Workflow、global distribution。

4.1 需求澄清#

Functional requirements：

创建 / 上传 image、video、audio、3D、effect、template、animation asset。 · 运行 AI generation / editing / tagging / transcoding workflow。 · 管理 asset version、dependency、license、owner、region、policy、provenance。 · review、publish、roll back、revoke，并在多产品和多区域分发。 · Workflow editor 可创建 versioned DAG，运行、暂停、取消、重试、replay。 · Agent 能检索知识、调用工具、生成或修改资产，但高风险动作需 approval。

Non-functional requirements：

100M logical assets；每个 asset 多版本、多 rendition、多 region replica。 · 1M peak distribution QPS；read-heavy，hot-key 极端明显。 · metadata p99 < 50 ms；cached manifest p99 < 20 ms；binary 由 CDN 提供。 · publish control plane 可接受秒级；AIGC / video / 3D 为秒到分钟级 async job。 · global active-active reads；write 使用 home-region ownership 或 cell-local leader。 · revoke / safety takedown 的传播 SLO 比普通 metadata freshness 更严格。

4.2 粗略容量估算（先声明 assumption）#

假设：

100M logical assets，平均 5 versions，平均每版 4 renditions。 · 每个 metadata/version/dependency 记录约 4 KB。 · CDN hit ratio 99.5%；峰值 distribution QPS = 1M。

则 metadata 量级：

100M \times 5 \times 4KB \approx 2TB

加 secondary index、replica、audit、dependency edge 后可能是 10–30 TB，不应把二进制放进 OLTP。

Origin QPS：

QPS_{origin} = 10^6 \times (1 - 0.995) = 5{,}000

平均 50 Mbps 的 10 秒视频约 62.5 MB；100M 个此类对象就是 PB 级。因此 binary、preview、embedding、transcode output 必须进入 object storage + CDN，metadata DB 只保存 immutable reference、checksum 和 policy。

4.7 Go：幂等创建 + Transactional Outbox#

go
type CreateAssetRequest struct {
	TenantID   string         `json:"tenant_id"`
	Type       string         `json:"type"`
	WorkflowID string         `json:"workflow_definition_id"`
	Inputs     map[string]any `json:"workflow_inputs"`
}

type AssetVersion struct {
	AssetID, VersionID, TenantID string
	State                        string
	Generation                   int64
}

func (s *Service) CreateAsset(ctx context.Context, idemKey string, req CreateAssetRequest) (*AssetVersion, error) {
	if idemKey == "" { return nil, ErrMissingIdempotencyKey }
	requestHash := stableJSONHash(req)

	var result *AssetVersion
	err := s.db.WithTx(ctx, func(tx Tx) error {
		prior, err := tx.GetIdempotency(ctx, req.TenantID, idemKey)
		if err == nil {
			if prior.RequestHash != requestHash { return ErrIdempotencyConflict }
			result = prior.Response
			return nil
		}

		result = &AssetVersion{
			AssetID: newULID(), VersionID: newULID(), TenantID: req.TenantID,
			State: "DRAFT", Generation: 1,
		}
		if err := tx.InsertAssetVersion(ctx, result); err != nil { return err }

		evt := OutboxEvent{
			ID: newULID(), AggregateID: result.AssetID, Type: "AssetCreated.v1",
			Payload: mustJSON(map[string]any{"asset": result, "workflow_id": req.WorkflowID}),
		}
		if err := tx.InsertOutbox(ctx, evt); err != nil { return err }
		return tx.SaveIdempotency(ctx, req.TenantID, idemKey, requestHash, result)
	})
	return result, err
}

解释重点：

  • HTTP retry、mobile 弱网、gateway timeout 都可能重复请求；exactly-once transport 不现实，业务使用 at-least-once + idempotent effect。
  • Idempotency-Key 还要绑定 canonical request hash，防止同一 key 被复用到不同 payload。
  • Outbox relay 可重复发布；consumer 用 event_id 或 (aggregate_id, generation) 去重。

4.8 Publish：一个可证明正确的 protocol#

text
1. Lock / compare generation of AssetVersion
2. Verify all required renditions READY and checksums valid
3. Verify policy/license/safety decision is current
4. Materialize immutable PublishSnapshot manifest
5. Atomically CAS asset.current_published_version
6. Commit PublishSnapshot + Outbox(Published)
7. Async: search index, cache warmup, CDN prefetch, cross-region replication

CAS(expected_generation) 防止两个 reviewer 同时发布不同版本。Index/CDN 是 projection，不参与主事务；失败可以从 outbox 重放。读路径只读已提交的 immutable snapshot，因此不会看到“半个版本”。

4.11 Failure drill#

Kafka 重复消息：consumer inbox/dedup；output atomic publish；禁止 “先 side effect 再记完成”。 GPU worker OOM：记录 input shape、model/version、batch；降低 batch / split job / change GPU class；retry mutation 有上限。 Object store slow：manifest 与 bytes 分离；range read、prefetch、locality cache；限制 fan-out 防止放大。 Regional outage：读切备用 snapshot；新写进入备用 home region 需要 fencing，不能双主脑。 Hot asset：CDN、regional cache、singleflight、prewarm；origin token bucket 保护。 Bad model rollout：version pin、shadow、canary、quality/latency/cost gate、one-click rollback。 Safety takedown backlog：单独高优先级 topic / worker pool，不和普通 metadata update 共用队列。

5.2 DAG compiler#

编译检查：

Kahn topological sort 检测 cycle，复杂度 \(O(V+E)\)。 · 上游 output schema 与下游 input schema 类型兼容。 · 必需 node / secret / model / tool version 存在。 · 每个 side-effect node 声明 idempotency strategy 与 compensation。 · 计算 critical path、parallel width、resource envelope、worst-case cost。

python
from collections import defaultdict, deque

def compile_dag(nodes: dict, edges: list[tuple[str, str]]):
    graph, indeg = defaultdict(list), {n: 0 for n in nodes}
    for u, v in edges:
        if u not in nodes or v not in nodes:
            raise ValueError("unknown node")
        if not schema_compatible(nodes[u]["output"], nodes[v]["input"]):
            raise TypeError(f"{u} -> {v} schema mismatch")
        graph[u].append(v)
        indeg[v] += 1

    ready = deque([n for n, d in indeg.items() if d == 0])
    order = []
    while ready:
        u = ready.popleft()
        order.append(u)
        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                ready.append(v)
    if len(order) != len(nodes):
        raise ValueError("workflow contains a cycle")
    return order

Agent loop 可能有逻辑循环，不能直接当静态 DAG。做法是把 AgentLoop 封装成一个有严格 max_steps / deadline / token_budget / tool_budget / stop_condition 的 node；外层 workflow 仍然可恢复。

5.3 Scheduler 与 lease#

text

 -> tenant quota / priority / deadline

Worker 超时后 scheduler 可重新派发，因此旧 worker 可能“复活”。所有写入带 fencing_token，storage 只接受更大的 token；这比仅靠 heartbeat 能更可靠地阻止 zombie write。

5.4 Go：状态转换与 optimistic concurrency#

go
var allowed = map[string]map[string]bool{
	"QUEUED":  {"RUNNING": true, "CANCELED": true},
	"RUNNING": {"WAITING": true, "SUCCEEDED": true, "FAILED": true, "CANCELED": true},
	"WAITING": {"RUNNING": true, "FAILED": true, "CANCELED": true},
}

func (s *RunStore) Transition(ctx context.Context, runID, from, to string, generation int64) error {
	if !allowed[from][to] { return ErrInvalidTransition }
	res, err := s.db.ExecContext(ctx, `
		UPDATE workflow_run
		SET state = ?, generation = generation + 1, updated_at = NOW()
		WHERE run_id = ? AND state = ? AND generation = ?`,
		to, runID, from, generation)
	if err != nil { return err }
	n, _ := res.RowsAffected()
	if n != 1 { return ErrConcurrentUpdate }
	return nil
}

5.5 Replay / debug#

一次 run 必须串起：

text
request_id -> definition/version -> run_id -> task/attempt
           -> input/output artifact checksum
           -> model/prompt/tool/policy version
           -> resource pool/GPU -> trace -> cost -> eval result

Replay 分两类：

Deterministic replay：使用原 input artifact、版本、seed，重放 deterministic nodes；验证 runtime bug。 · What-if replay：固定输入，替换 model/prompt/tool version；用于 offline evaluation，不得覆盖原结果。

日志不能只显示 “node failed”。UI 要呈现 error category、attempt、upstream lineage、resource wait、model latency、tool response、policy decision 和可操作的 retry / rollback。

5.6 Cancel / retry / compensation#

  • Cancel 是 desired state；coordinator 停止派发新节点，向运行节点发 cancellation token。
  • GPU kernel / external API 不一定可立即停止；结果完成后仍要检查 run generation，过期结果丢弃。
  • Pure compute node 可自动 retry；side-effect node 需要 idempotency key。
  • Publish / charge / notify 等动作若已部分成功，使用 Saga compensation 或人工 repair，不假装 distributed transaction。

8.4 Backpressure#

令 arrival rate 为 \(\lambda\)，service rate 为 \(\mu\)。稳定队列需要：

import torch
import torch.nn as nn
import torch.nn.functional as F

class AlignedEmbeddingModel(nn.Module):
    def __init__(self, image_encoder, text_encoder, in_img, in_txt, dim=768):
        super().__init__()
        self.image_encoder = image_encoder
        self.text_encoder = text_encoder
        self.image_proj = nn.Linear(in_img, dim, bias=False)
        self.text_proj = nn.Linear(in_txt, dim, bias=False)
        self.logit_scale = nn.Parameter(torch.tensor(1 / 0.07).log())

    def forward(self, images, token_ids, attention_mask):
        zi = F.normalize(self.image_proj(self.image_encoder(images)), dim=-1)
        zt = F.normalize(
            self.text_proj(self.text_encoder(token_ids, attention_mask)), dim=-1
        )
        scale = self.logit_scale.exp().clamp(max=100)
        logits = scale * zi @ zt.T
        labels = torch.arange(logits.size(0), device=logits.device)
        loss = (F.cross_entropy(logits, labels) +
                F.cross_entropy(logits.T, labels)) / 2
        return loss, zi, zt

9.2 Diffusion / flow 的必懂数学#

Forward diffusion：

q(x_t|x_0)=\mathcal N(\sqrt{\bar\alpha_t}x_0, (1-\bar\alpha_t)I)

训练常见 noise-prediction objective：

\mathcal L=\mathbb E_{x_0,t,\epsilon} \left[\|\epsilon-\epsilon_\theta(x_t,t,c)\|_2^2\right]

Classifier-free guidance：

\hat\epsilon=(1+w)\epsilon_\theta(x_t,t,c) -w\epsilon_\theta(x_t,t,\varnothing)

较大 \(w\) 提高 prompt adherence，但可能降低 diversity、产生饱和和 artifact。Production 不能只调 guidance scale，还要看 sampler steps、resolution、control signal、latency、safety。

Flow matching 可学习 velocity field \(v_\theta(x_t,t,c)\)，推理求解 ODE：

\frac{dx_t}{dt}=v_\theta(x_t,t,c)

它常能用更直接的 transport path；面试重点不是比较口号，而是 step count、quality、stability、distillation、serving cost。

9.3 PyTorch：简化的 conditional diffusion training step#

python
def diffusion_train_step(vae, text_encoder, denoiser, batch, scheduler):
    with torch.no_grad():
        z0 = vae.encode(batch["image"]).latent_dist.sample() * vae.scale
        cond = text_encoder(batch["tokens"], batch["mask"])

    noise = torch.randn_like(z0)
    t = torch.randint(0, scheduler.num_train_steps,
                      (z0.size(0),), device=z0.device)
    zt = scheduler.add_noise(z0, noise, t)

    # Randomly drop text conditioning for classifier-free guidance training.
    drop = torch.rand(z0.size(0), device=z0.device) < 0.1
    cond = torch.where(drop[:, None, None], torch.zeros_like(cond), cond)

    pred = denoiser(zt, t, encoder_hidden_states=cond).sample
    loss = torch.nn.functional.mse_loss(pred.float(), noise.float())
    loss.backward()
    torch.nn.utils.clip_grad_norm_(denoiser.parameters(), 1.0)
    return loss.detach()

10.3 vLLM 的核心：PagedAttention + continuous batching#

传统 KV cache 为每个 request 预留连续大块显存，长短请求混合会产生 fragmentation / waste。PagedAttention 将 KV cache 分 page/block 管理，按需映射逻辑 block 到物理 block；continuous batching 在请求完成时立即加入新请求，不等整个 static batch。

近似 KV cache bytes（decoder-only）：

B_{KV}\approx 2 \times L \times T \times H_{kv} \times D_h \times b

其中 2 是 K/V，\(L\) 层数，\(T\) token 数，\(H_{kv}\) KV heads，\(D_h\) head dimension，\(b\) 每元素 bytes。GQA/MQA 通过减少 \(H_{kv}\) 大幅降 KV memory。

指标必须分开：

TTFT (Time To First Token)：受 queue、prefill、prompt length 影响。 · TPOT (Time Per Output Token)：受 decode scheduling、batch、GPU 影响。 · tokens/s、request p95/p99、queue age、KV cache hit/usage、preemption、OOM。

10.4 LLM admission control#

不要只按 request count autoscale。估算工作量：

Work = \sum_i (\alpha T^{prompt}_i + \beta T^{expected\ output}_i)

Prefill 通常 compute-heavy，decode memory-bandwidth / KV-sensitive。Admission 根据 live tokens、KV blocks、deadline、tenant quota，而不是让所有请求进入 GPU 后 OOM。

Prefix cache 复用相同 system prompt / document prefix 的 KV block；semantic cache 复用语义相近的最终结果。两者风险不同：semantic cache 必须将 tenant、ACL、model/prompt version、policy、freshness 放进 key / validation，不能跨用户泄漏结果。

10.6 GPU placement 与 bin packing#

目标不是“GPU utilization 100%”，而是在 SLO 下提高 useful work / dollar。一个简化目标：

Score(p,w)=a\cdot Locality+b\cdot Fit-c\cdot Fragmentation -d\cdot QueueRisk-e\cdot MigrationCost

MIG 适合隔离可预测的小模型 workload；大模型 TP/PP 需要整卡/多卡拓扑。Placement 考虑 VRAM、SM、memory bandwidth、NVLink topology、model residency、batchability、priority。GPU util 高但 queue / p99 爆炸不是成功。

10.7 Autoscaling#

Reactive signals：queue age、p95 latency、live tokens、GPU memory、batch fullness。Proactive signals：scheduled launches、historical seasonality、model preload time。Scale-down 要考虑 model load / warmup 成本，并用 hysteresis 防抖动。

Little's Law 用于 sanity check：

L=\lambda W

若到达 2,000 req/s，端到端平均 0.5 s，则系统平均约有 1,000 个 in-flight request。实际 capacity 要按 p99、burst、failure headroom 设计。

12.2 Risk score 与 threshold#

Binary classifier：

Precision=\frac{TP}{TP+FP},\quad Recall=\frac{TP}{TP+FN},\quad F_\beta=(1+\beta^2)\frac{PR}{\beta^2P+R}

当漏过高危内容代价远高于误杀时选 \(\beta>1\) 强调 recall，但最终阈值应最小化业务成本：

20.2 Go：Token Bucket（单进程核心逻辑）#

go
type Bucket struct {
	mu       sync.Mutex
	capacity float64
	tokens   float64
	rate     float64 // tokens per second
	last     time.Time
}

func (b *Bucket) Allow(cost float64, now time.Time) bool {
	b.mu.Lock()
	defer b.mu.Unlock()

	elapsed := now.Sub(b.last).Seconds()
	b.tokens = math.Min(b.capacity, b.tokens+elapsed*b.rate)
	b.last = now
	if cost > b.tokens { return false }
	b.tokens -= cost
	return true
}

21. System Design 高频追问：短答案必须能继续深挖#

Q1：为什么 asset metadata 不全放 object storage？#

Object storage 适合 immutable large blobs，但 lifecycle CAS、secondary query、transaction、dependency update 不方便。OLTP 保存 authoritative metadata/version，object store 保存 bytes/manifest；analytical table/index 是 projection。

Q2：为什么 publish 用 snapshot？#

Snapshot 把 version、rendition、policy 固化成 immutable unit，读者要么看到旧完整版本，要么看到新完整版本，不会半发布；CDN key 稳定、可回滚。

Q3：1M QPS 最大风险是什么？#

通常不是平均 QPS，而是 hot asset、regional launch、cache miss storm、policy revoke。CDN + regional cache + singleflight + jitter TTL + origin limiter；revoke 走独立高优先级 invalidation。

Q4：为什么不用一个大 workflow engine 处理全部？#

Durable orchestration、tensor inference、token generation、batch processing 的 latency/failure/scaling model 不同。统一 domain contract 与 observability，执行 runtime 分层；workflow engine 不应调每个 token。

Q5：为什么 Agent 不直接调用 publish API？#

LLM 输出不可信。必须经过 structured schema、auth scope、policy、idempotency、approval 和 audit；高风险 publish 展示 exact asset/version/targets 给人确认。

Q6：怎么保证 workflow retry 不重复生成 / 收费 / 发布？#

At-least-once + deterministic operation key + idempotency record；output atomic publish；side effect 使用 provider idempotency key / compensation；fencing token 阻止 zombie attempt。

Q7：怎么 debug “workflow 很慢”？#

按 critical-path trace 分 queue、artifact I/O、CPU preprocessing、GPU wait、model compute、tool/API、publish；看版本与 slice 聚集，不能把并行 task duration 全相加。

Q8：GPU utilization 为什么不是越高越好？#

高 util 可能来自 queue overload 或低价值 workload。目标是 SLO 下的 useful output / dollar，同时看 queue age、p99、batch fullness、OOM、cost per success、quality。

Q9：vLLM 与 Ray Serve 怎么一起用？#

Ray Serve 组织 multimodal / RAG / tool DAG 与 routing，vLLM 是 LLM generation backend；二者通过 typed request / streaming response / telemetry contract 连接，不让 Ray actor 自己重新实现 token scheduler。

Q10：new model 怎么上线？#

Offline golden/adversarial → shadow → canary by intent/tenant → quality/safety/latency/cost gate → progressive rollout → rollback window。Artifact / trace pin model version。

Q11：如何把 workflow 做到可扩展？#

Versioned node contract、schema validation、resource profile、idempotency strategy、observability hooks；registry 与 runtime adapter 解耦。新 node 不是随便上传 Python，而是有 sandbox、permission、owner、eval、rollout。

Q12：RAG 为什么会越权？#

若先检索再由 prompt 判断权限，内容已进入 context。必须在 retrieval/filter 层用 caller identity + document ACL，cache key 也带 tenant/permission generation；不确定 fail closed。

Q13：如何处理 workflow schema evolution？#

Definition immutable version；additive backward-compatible change；breaking change 新 node/schema version + adapter + dual-run；已开始 run pin 原 definition，不被热更新改变。

Q14：multi-region 写入冲突怎么办？#

Asset 指定 home region / cell leader，generation 单调递增；failover 使用 fencing。Global read active-active，但避免同一 aggregate 无约束 multi-master。

Q15：Search index 落后怎么办？#

监控 event-to-index lag、per-partition watermark；读取关键新资产可 dual-read metadata fallback。Index 是 projection，可 replay/rebuild；ACL/safety change 不能只依赖普通 eventual update。

class SharedEmbeddingModel(torch.nn.Module):
    def __init__(self, image_encoder, text_encoder,
                 image_dim, text_dim, out_dim=768):
        super().__init__()
        self.image_encoder = image_encoder
        self.text_encoder = text_encoder
        self.image_proj = torch.nn.Linear(image_dim, out_dim, bias=False)
        self.text_proj = torch.nn.Linear(text_dim, out_dim, bias=False)
        self.logit_scale = torch.nn.Parameter(
            torch.tensor(1 / 0.07).log()
        )

    def encode_image(self, pixels):
        h = self.image_encoder(pixels).pooler_output
        return torch.nn.functional.normalize(
            self.image_proj(h), dim=-1
        )

    def encode_text(self, token_ids, attention_mask):
        h = self.text_encoder(
            token_ids, attention_mask=attention_mask
        ).last_hidden_state[:, 0]
        return torch.nn.functional.normalize(
            self.text_proj(h), dim=-1
        )

    def contrastive_loss(self, image_z, text_z):
        scale = self.logit_scale.exp().clamp(max=100)
        logits = scale * image_z @ text_z.T
        labels = torch.arange(
            logits.shape[0], device=logits.device
        )
        return 0.5 * (
            torch.nn.functional.cross_entropy(logits, labels)
            + torch.nn.functional.cross_entropy(logits.T, labels)
        )

    async def __call__(self, example):
        return await self.score_batch(example)

Fractional GPU 是共享调度，不等于物理隔离。只有 model memory/compute profile 证明可以安全 co-locate 才用；强隔离用 MIG 或独占 GPU。LLM generation 走 vLLM 独立 pool，不与 embedding/reranking 共用 queue，因为 KV-cache、prefill/decode、latency model不同。

BM25 score 与 cosine score分布不同，第一版用 Reciprocal Rank Fusion：

RRF(d)=\sum_s\frac{w_s}{k+rank_s(d)}
python
def rrf(result_sets, weights=None, k=60, limit=2000):
    weights = weights or {
        source: 1.0 for source in result_sets
    }
    merged = {}
    for source, hits in result_sets.items():
        for rank, hit in enumerate(hits, start=1):
            key = (hit.asset_id, hit.asset_version)
            row = merged.setdefault(key, {
                "asset_id": hit.asset_id,
                "asset_version": hit.asset_version,
                "rrf": 0.0,
                "source_ranks": {},
            })
            row["rrf"] += weights[source] / (k + rank)
            row["source_ranks"][source] = rank
    return sorted(
        merged.values(), key=lambda x: x["rrf"], reverse=True
    )[:limit]

候选数量不是固定真理。实战答法：

ES/Milvus 各取数百到一千，取决于 filter selectivity 与 recall benchmark。 · Union约 1K–2K 后做 cheap feature rank。 · Top 100–300 才跑 expensive cross-encoder。 · Load高时可跳过 heavy rerank，但绝不能跳过 ACL/policy。 · 每一层用 Recall@K / nDCG / p95 / cost做 cascade ablation。

Reranker score：

S=w_1S_{cross}+w_2S_{vector}+w_3S_{BM25} +w_4Quality+w_5Freshness+w_6Personalization -\lambda DuplicatePenalty

ACL/license/safety不是负分，而是先过滤。

25.14 面试官 likely ask：直接答案#

Q：BM25存在哪里？ A：Elasticsearch inverted index。Original/derived text的durable copy在object/lake；ES是serving projection，可从event/snapshot重建。

Q：Embedding存哪里？ A：Lance/Parquet on object storage存versioned durable snapshot；Milvus存online ANN projection。OLTP只存vector reference/version，不存巨大array。

Q：为什么Lance + Milvus？ A：Lance面向offline scan/backfill/eval/rebuild，Milvus面向online distributed ANN。Milvus丢collection时可从Lance generation重建。

Q：为什么Milvus + Elasticsearch？ A：ES负责BM25、exact filter、ACL/license metadata；Milvus负责dense ANN。Query并行retrieve后fusion/rerank。代价是dual-projection consistency，所以必须有asset/version/generation/reconciler。

Q：Ray端到端怎么用？ A：Ray Data跑GPU embedding backfill，class actor复用model；Ray Serve跑online query encoder/reranker并batch/autoscale；Ray Core可做heterogeneous fan-out。Durable DAG、policy、asset version不放Ray内存当truth。

Q：GPU怎么assign？ A：Workflow先映射resource profile；KubeRay/K8s选GPU node pool，Ray用num_gpus/custom resource调度；model actor warm resident，按queue/batch/p95扩容。Fractional GPU只在memory profile允许时co-locate；强隔离用MIG/独占卡。

Q：如何避免GPU空转？ A：CPU decode与GPU stage分离、bounded prefetch、shape/modality bucketing、dynamic batching、warm actors、locality。先分解data wait和compute，不盲目加GPU。

Q：Embedding model升级怎么做？ A：新Lance snapshot + shadow Milvus/ES generation；snapshot K后replay delta；offline Recall/nDCG/filter，shadow/canary，atomic pointer switch；旧generation warm rollback。

Q：如何保证delete/policy及时？ A：先写authoritative deny generation让read fail closed，再高优先级event清ES/Milvus/cache/neighbor；不等普通index freshness。

Q：Reranking为什么不是直接用vector score？ A：Vector只表达共享空间相似度；产品还要lexical exactness、quality、freshness、context、diversity。先hard policy，再multi-stage rank；heavy cross-encoder只跑top N。

Q：50B怎么扩到100B？ A：不是把一个index翻倍，而是cell routing、modality/tenant/region partition、hot/warm/cold tier、PQ/disk ANN、head neighbor cache、generation backfill。Capacity从vector bytes、replica、index amplification和QPS反推。

25.15 3分钟项目答案#

我在Axxxx Search & Discovery做过50B+ multimodal assets的vector-lexical platform。Raw media放object storage，Kafka/Flink负责versioned ingestion和nearline normalization。Caption、OCR、ASR、tags进入Elasticsearch inverted index做BM25和hard metadata filter；aligned encoder产生的embedding以model/preprocess/version写入durable Lance/Parquet snapshot，online ANN projection放Milvus。这样Milvus负责低延迟similarity search，Elasticsearch负责lexical和ACL/license filter，两者都可以从source snapshot/event重建。

Query进来先authorize和解析filter，online query encoder生成与asset index兼容的vector；ES BM25与Milvus ANN并行retrieve，先用RRF合并，再做authoritative policy filter和real-time feature join。Cheap ranker把约千级candidates降到百级，heavy reranker只处理top N，最后做duplicate/diversity。这个multi-stage/asynchronous retrieval与A/B testing带来15% discovery CTR提升。

Ray在后续shared AI Infra里有明确边界：résumé可确认的是Ray Serve/KubeRay、async routing和shared CPU/GPU execution。Online encoder/reranker可以作为独立Ray Serve deployment做batching和autoscaling；LLM generation交给vLLM独立pool。大规模backfill只有在真实系统确实使用Ray Data时才这样讲，否则按实际Spark/Airflow/Argo路径回答。Durable asset version、checkpoint、policy和days-long workflow不放Ray内存，而由intent/execution control plane管理。

GPU assignment从resource profile出发：weights、activation、workspace、cache和headroom决定独占卡、MIG还是fractional GPU；KubeRay/Kubernetes选择node pool，Ray scheduler按num_gpus/custom resource放actor。Autoscaling看queue age、batch fullness、p95和OOM，不只看GPU utilization。

Model/index rollout用generation：新encoder回填新Lance snapshot，构建shadow ES/Milvus，replay delta，做Recall/nDCG/critical policy slice、shadow和canary，再CAS active pointer；旧generation保持warm rollback。这些version、projection consistency、GPU execution和failure recovery细节，是我会重点深挖的真实production部分。
